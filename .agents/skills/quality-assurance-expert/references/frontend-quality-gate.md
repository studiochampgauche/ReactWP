# Frontend Quality Gate

Use this gate whenever user-facing rendering, React, SCSS, media, interaction, motion, accessibility, performance, client navigation, or a shared render mode can be affected. Read the specific references routed by `frontend-expert` before applying this checklist.

## Architecture and ReactWP Contracts

- Source changes live in `src/`; generated `dist/` output was not hand-edited.
- The implementation uses the existing template registry, loader, page-transition, scroller, route service, media groups, and runtime extension points instead of parallel services.
- Universal code is deterministic and avoids unguarded browser globals during static/server rendering.
- Template names and expected route data match backend values exactly.
- Direct load, hydration, and internal navigation preserve current content, title/head state, focus/scroll behavior, and route lifecycle.
- Effects, listeners, observers, timers, GSAP contexts/timelines, ScrollTriggers, and media-query handlers are scoped and cleaned up under remount, interruption, and repeated navigation.
- The first-paint strategy uses ReactWP's existing shell/Loader contract rather than a parallel page preloader. Client/static/server behavior explicitly records whether the loader is active or intentionally skipped, and critical CSS/template/font/media readiness prevents an unstyled route, fallback-font flash, hydration pop, or unstable layout from becoming visible.

## Content and Component Resilience

- For visible editorial content, frontend and content/SEO use one authoritative composition matrix with a named single custodian/revision and both approvals; no divergent handoff copy exists. The joint rendered sign-off covers meaning/priority, semantic levels, real and edge lengths, type roles/measure, text-media relationships, responsive/locale behavior, and unresolved cases.
- The composition matrix includes one page-level media plan: each important asset or deliberate omission has a purpose, expected subject/source, supplied/pending/optional status, format, ratio/scale, focal/crop intent, caption/alt/credit needs, text relationship, responsive transformation, loading priority, and approved missing-media outcome.
- Semantic structure expresses the page hierarchy; components do not choose headings solely by appearance.
- Long/short/missing CMS content, absent/slow/error media, empty collections, and translated strings do not break layout or meaning.
- Necessary copy is not made to fit by indiscriminate type shrinking, clipping, hiding, fixed-height overflow, text-as-image, or an unapproved line clamp.
- Loading, empty, error, disabled, active, hover, focus-visible, and completed states exist where the interaction requires them.
- Plain strings render through JSX. Unchanged rich HTML has a documented trusted/sanitized source and a small explicit `dangerouslySetInnerHTML` boundary. `html-react-parser` appears only when tree transformation is actually required and is not treated as sanitization.
- Links use the correct internal/external behavior without breaking modified clicks, downloads, targets, keyboard use, or route transitions.

## Responsive, Input, and Visual Quality

- Every submitted/persisted field references the same authoritative contract revision as backend. Native attributes, visible format, allowed characters/positions, limits, locale assumptions, transport value, stable error mapping, and accessible instructions match that contract.
- Formatting is exercised through typing at every caret position, deletion, selection replacement, paste, drag/drop, autofill, mobile keyboard, IME/composition, undo/redo, browser restoration, and programmatic submission as applicable. A `keydown`, `pattern`, `type`, `inputMode`, or disabled-submit check alone cannot pass.
- Invalid client input is prevented or reported without silently changing meaning, trapping caret/focus, rejecting legitimate locale/Unicode/assistive input, losing recoverable values, or hiding an authoritative backend error.
- For reference-led work, the inspiration evidence includes a current whole-site coverage manifest, every distinct public template, a complete top-to-bottom homepage pass, desktop/mobile inspection, hover/click/scroll/drag/menu interaction testing, typography/spatial/media measurements, container grammar, and explicit `UNVERIFIED` gaps. Earlier notes or screenshots alone do not pass this requirement.
- Reference support is context-matched. Every adopted device cites evidence with the same role/content type, comparable frequency/density, scale/adjacency, interaction/state and responsive transformation. An occurrence anywhere in the pool does not license a local or repeated pattern; cherry-picked evidence is `FAIL`.
- When references improve an existing page, one authoritative current-to-target delta ledger covers every major region and classifies it as `keep`, `transform`, `remove`, or `replace with supplied/pending media`. It includes current rendered evidence, driving same-context evidence, required visible result and final desktop/mobile verification. A missing ledger, a post-hoc ledger, or a row whose result changed only copy, selector names, palette, radius, typeface or motion timing is `FAIL`.
- The rendered page matches its primary-carrier map. Each major section is intentionally carried by content/typography, supplied or visibly reserved pending media, a genuine artifact/data view, interaction, or deliberate quiet. A promised media/artifact role collapsed into more text or replaced with an interchangeable abstract graphic is `FAIL`; a mechanical image quota is also `FAIL`.
- The authoritative influence map contains separate `Header` and `Footer` rows naming directly observed reference principles or documented project-specific decisions. Each row covers structure/content, desktop/mobile transformation, interactions, accessibility constraints and originality boundary; a deliberate omission explains the replacement navigation/orientation/end-of-journey behavior. Missing, vague, styling-only or post-hoc rows are `FAIL`.
- Every prominent custom graphic family has an authoritative `Graphic / illustration` influence-map row created before implementation hardened. It states a valid role, real project/content/brand evidence, the driving inspected reference principle, transformed motif/medium, relationship to adjacent content, desktop/mobile composition, interaction/motion and reduced state, semantics, provenance, and originality boundary. If graphics were intentionally omitted, the map records how content, real media, typography, or whitespace carries the composition.
- Reference-led editorial work has a `Media rhythm` influence-map row based on observed evidence. The rendered page deliberately combines text-led, media-supported, media-led, large/full-bleed, and quiet moments as appropriate; uninterrupted text caused by missing assets and a mechanical one-image-per-section quota are both `FAIL`.
- Reference-led work has an authoritative `Interface devices / intentional absence` row and ledger covering buttons/text links, contextual pretitles/uptitles/kickers, visible labels, item numbers, badges/status/tags, standalone trailing emphasis/fact lines, literal code/data, panels/cards/surfaces, dividers/metadata systems, header and footer. Directly observed absence is recorded. A family absent from every active reference and unnecessary to real content/state/order/interaction is omitted; an undocumented or polish-only divergence is `FAIL`.
- Header QA covers initial/scrolled/theme states, navigation hierarchy, active state, logo and action treatment, hover/focus, menu open/close, keyboard/Escape/focus restoration, touch/mobile layout and transition into the first content. Footer QA covers the preceding-section transition, content architecture, navigation/contact/legal grouping, visual focal point, hover/focus/final motion, mobile reading order and end-of-page behavior.
- Every major section traces to an observed reference principle, a real product/content constraint, or a documented deliberate original decision. References materially affect architecture, density, typography, media, rhythm, responsive transformation or interaction rather than only decorative tokens.
- Every repeated card/surface passes the card audit: it communicates a real content boundary, comparison, state or interaction; its treatment is reference/project-supported; and an open row/list/editorial/table/timeline/media alternative would be less appropriate. Unsupported equal rounded-card grids, nested panels and repeated icon-title-copy recipes are `FAIL`.
- The component-grammar audit covers compact kickers/eyebrows, indices, badges/status, metadata rails, code-like text, divider grids, label-title-copy-detail rows, boxed process steps, CTA recipes, and header/footer utility treatments regardless of their class names. Each instance must add unique semantic/interaction value and be supported by real content or observed reference evidence. Redundant labels, decorative numbering, ordinary prose styled as code, repeated slogan rails, equal boxed flows without real nodes/states, habitual capsule-arrow button pairs, and ornamental technical page chrome are `FAIL`.
- Equal repeated panels built from a small identifier/label, oversized heading, short paragraph, borders and unused space fail unless they represent a true object, state, comparison, or interaction and match the authoritative reference/content grammar. Renaming selectors or changing radius, color, motion, or orientation cannot pass the audit.
- Repeated trailing `<strong>` elements or equivalent small bold/colored/uppercase/monospace lines fail when they merely finish a block, repeat nearby meaning, expose an unnecessary implementation detail, or manufacture another hierarchy level. A necessary fact must use the appropriate prose, caption, name/value, tag/status, or data semantics and pass the reference/content removal test.
- Required semantic form labels, accessible names, genuine application controls, real status, true order, and literal code are not removed to imitate a sparse reference. QA distinguishes their necessary semantics from an unsupported decorative presentation layer.
- Page-level repetition is reviewed separately from local validity: a device that is defensible once still fails when repeated into a mechanical technical aesthetic that overrides content and reference character.
- Prominent illustrations, diagrams, SVG/canvas/3D fields, and decorative visual systems pass the graphic-specificity audit. An interchangeable abstract technology composition, arbitrary data-like geometry, or animation used only to occupy space is `FAIL`; labels and brand colors alone cannot supply meaning. Real data/topology, subject matter, brand language, and transformed reference evidence may justify otherwise familiar forms.
- The final genericity test confirms that removing the logo, brand color and images would not leave an interchangeable AI/SaaS template whose nouns could be swapped for an unrelated company.
- The frontend did not invent statistics, testimonials, ratings, logos, awards, people, badges, decorative feature icons or claims to fill a visual pattern; every visible proof/content asset comes from an approved source or is explicitly identified as placeholder content.
- The visual concept and hierarchy remain coherent at narrow mobile, intermediate, desktop, and relevant wide widths.
- Layout adapts structurally rather than only shrinking; overflow, viewport units, safe areas, fixed/sticky content, and dynamic browser chrome are considered.
- Every fixed, sticky, or ScrollTrigger-pinned composition has a documented usable-scrollport calculation and fit decision for each active state. Persistent headers/toolbars, safe areas, padding, loaded fonts/media, real plus longest CMS/translated content, captions/actions/errors, short landscape height, mobile browser chrome, and zoom/text enlargement are included. A width-only screenshot is insufficient evidence.
- During a sequential pin, every essential item becomes fully visible before release, preserves logical DOM/focus order and reverse-scroll comprehension, and is immediately available in the reduced-motion/no-pin path. Content permanently below an oversized title/media layer, clipping/`overflow: hidden`, unreadable type shrinking, or an undiscoverable nested scroll area is `FAIL`.
- Touch, mouse, keyboard, coarse/fine pointer, hover/no-hover, zoom, and orientation behavior are appropriate to the feature.
- Pending user/CMS media uses stable responsive placeholder geometry, a restrained project/reference-supported background, and a traceable asset request. It is not presented as finished proof, does not contain unrequested AI or copied reference imagery, and has an approved path to semantic media or a no-media composition.
- Supplied media uses semantic image/video markup when informative, stable dimensions/aspect ratio, correct crop/focal behavior, useful alternatives, captions/transcripts/controls where required, and predictable loading priority. Large/full-bleed or near-viewport media remains usable with mobile browser chrome, safe areas, zoom, reduced motion, and constrained bandwidth.
- Design tokens and component styles are reused consistently; literal exceptions are intentional and local.
- Visual comparison uses the requested references/influence map without copying or losing the project's own hierarchy.

## Accessibility

- Landmark, heading, list, control, label, name/role/value, and reading order are correct.
- Every interactive element is keyboard reachable and operable with visible focus; focus is moved/restored deliberately for navigation and overlays.
- Contrast, text resizing/zoom, target size, error messaging, status announcements, and non-color cues are verified where applicable.
- Reduced motion removes nonessential motion without hiding content or breaking orientation.
- Images, video, audio, canvas, and animated content expose equivalent information through alt text, captions, transcripts, or nearby content as appropriate.

## Performance and Motion

- Rendering choice, bundle cost, asset priority, font/media loading, and third-party work match the feature's value.
- Loader copy in a project webfont is hidden by server-emitted critical CSS before JavaScript runs, references an exact applicable `criticalFonts` face/weight, and becomes visible only after its specific `document.fonts.load()` plus positive `document.fonts.check()` result. Its entrance is fluid and layout-stable; font failure keeps decorative copy hidden without blocking loader completion. Waiting on every font, revealing a fallback face, or gating only from late JavaScript is `FAIL`.
- The loader has no arbitrary minimum duration, exits promptly after real critical readiness, has a reduced-motion final state, and cannot permanently cover usable content on font/resource/JavaScript failure. A prerendered route that skips or forces the loader does so deliberately and is verified in that mode.
- Layout shift is controlled and critical content is not delayed behind animation or decorative media.
- CSS handles simple state transitions; GSAP is reserved for sequencing, interruption, scroll linkage, or runtime control.
- Animation targets transform/opacity where practical, avoids layout thrashing, and remains correct during rapid navigation, resize, and reduced motion.
- Pin eligibility and measurements are recalculated after relevant font/media/CMS/viewport changes without continuous layout thrashing; observers/listeners and rebuilt ScrollTriggers are scoped and cleaned up.

## Required Evidence

- Inspect source and affected consumers.
- For each active live-site reference, inspect the recorded route/template coverage, homepage scroll narrative, interaction matrix, viewports, measurements, container grammar, inspection date, and blocked evidence before accepting the influence map.
- Inspect the section-level influence map, card/surface audit, component-grammar audit and genericity-test result against the rendered page, including header, actions, and footer; a written claim without visible structural influence does not pass.
- Compare every rendered interface-device family with the authoritative presence/absence ledger. Inspect the actual reference evidence and removal-test result; fail devices justified only by balance, polish, technical tone, component-field availability, or an agent assertion.
- Compare rendered desktop/mobile header and footer evidence directly with their authoritative influence-map rows. Reject a shell whose reference influence is limited to color, typeface, radius, logo placement or a generic menu animation.
- Compare each prominent graphic at desktop/mobile and in its still/reduced-motion state with its authoritative art-direction row. Verify that its role remains legible without relying only on labels or brand color, that explanatory relationships are truthful, decorative semantics are appropriate, and reference influence materially changed more than palette or motion polish.
- Compare the rendered page's media cadence and each pending slot against the authoritative composition matrix and `Media rhythm` row. Verify desktop/mobile scale, crop/focal intent, large/full-bleed transitions, placeholder status, asset provenance, semantic replacement plan, no-media fallback, and loading priority; record unavailable final assets as pending rather than pretending visual completion.
- For an existing reference-led page, inspect the current baseline and final result at matching viewports and states. Verify every affected delta-ledger row across first viewport, section architecture, primary carriers/media, typography, interface-device density, actions, header/menu, footer transition and end state; written intent without a visible delta does not pass.
- Trace every reference-derived device back to same-role evidence and verify its local frequency, scale, adjacency, interaction and responsive behavior against that evidence. Reject permission inferred solely from an unrelated occurrence elsewhere in the active set.
- For every pin/sticky/fixed region, record start/mid/end and forward/reverse observations at representative widths and heights, including an ordinary laptop, shortest supported viewport/landscape, longest real content, loaded fonts/media, zoom/text enlargement, mobile viewport change, and reduced motion. Confirm the actual visible bounds of every essential item, not only trigger markers or a successful animation.
- Run the smallest relevant theme/build/render/lifecycle tests from `configs/`.
- For loader or first-paint work, record cold/warm cache and throttled observations from the server-emitted frame through exit, including the exact loader-font success and failure paths, reduced motion, client/static/server loader skip/force behavior, hydration, and a no-trap JavaScript/resource failure path.
- Exercise the real journey at representative widths and input modes.
- Run the shared form fixtures through the frontend and record browser-input plus backend-error-mapping observations for affected fields.
- Record visual, keyboard, focus, reduced-motion, loading/error, and navigation observations that automated tests do not prove.

A successful theme build alone cannot pass this gate.
